== アーキテクチャメモ
=== 技術選定
* ランタイム：Deno (`deno desktop`コマンドでネイティブアプリ化)
** deno desktopは実験的機能(Deno 2.9時点でcanaryビルド)
* 出力形式：ブラウザ不要でOSごとのネイティブバイナリとして
* 描画バックエンド：OS標準WebView
** CEFにすると見た目統一できるが重くなるので不採用

=== ウィンドウ設計
`Deno.BrowserWindow`のオプションでキャラクターを表示する

* `alwaysOnTop: true` — 常に最前面
* `frameless: true` — タイトルバー・枠なし
* `noActivate: true` — フォーカスを奪わない浮遊パネル
* クリックスルー対応は未確認、実装前に要調査

=== キャラクター切り替え設計
* アプリは1バイナリに統一(犬・猫・チンチラごとにexeを分けない)
* `assets/dog/`, `assets/cat/`, `assets/chinchilla/`のように各キャラクター画像をフォルダごとに格納する
* 設定画面 or トレイメニューで選択 → 選択状態をJSON等にローカル保存し、次回起動時に復元
* 設定画面ではキャラクター選択を行えるようにし、キャラクターの状態や画面の表示サイズなどを調整できるようにする

=== アセット仕様
* 拡張子: PNG(背景透過必須)
* サイズ: 表示100〜150px、素材自体は256x256(高DPI対応のため2倍サイズで用意)
* アニメーション種別: idle:待機状態(3〜4枚) / walk:アクティブ①(4〜6枚) / sit:アクティブ②(2〜3枚) / drag:イベント(1〜2枚)
* 左右の向きは片方向だけ描いて`scaleX(-1)`で反転、枚数を節約
* とりあえずは棒人間のCSSデモで動作確認を行い、後から本番素材に差し替える方針

=== ビルド・配布
* ビルドは開発機1台でクロスコンパイル可能(`deno desktop --all-targets`)
* 出力: macOS(.app/.dmg) / Windows(.exeディレクトリ) / Linux(.AppImage)
* サーバー不要、アプリ自体がローカルでHTTPサーバーを内包
* 配布先: GitHub Releases(将来的にSteam展開も選択肢、その場合はSteamworks登録$100が必要)

=== CI/CD
* `jsr:@fry69/release-init`を導入し、GitHub Actionsでの自動ビルド・自動リリースを構築する方針
* フロー: タグpush → Actions起動 → `deno desktop --all-targets`相当のビルド → GitHub Releaseへアセット自動添付
* 自動更新機能(`release.baseUrl`)もGitHub Releasesを向き先にできるが、現状Windowsの自動更新は未対応

=== コード署名
* 現時点では未対応のまま進める方針(個人の無料配布のため)
* マネタイズする/個人事業主になるタイミングで検討
* macOS: Apple Developer Program($99/年) + Notarization必要
* Windows: コード署名証明書が必要(Microsoft Store経由なら証明書購入不要)
